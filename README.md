# (R)Evolution

The public notebook of the Mansus group: ideas, architecture, ideology, essays and influences we
won't build ourselves. Published at https://nemonoboru.github.io/revolution/.

The site is generated by [Eleventy](https://www.11ty.dev/) from markdown. Every file in
`src/articles/` appears in three places: on the landing page under its category key, as a strip
on the contents page (newest first, newest as the black cut-out), and as its own article page.
Why it looks the way it does: `design/README.md`.

## Run it locally

```sh
npm install
npm start        # http://localhost:8080/revolution/, rebuilds on save
npm run build    # writes the site to _site/
```

## Add or edit an article

Create `src/articles/<slug>.md`. The file name becomes the URL: `/revolution/articles/<slug>/`.

```markdown
---
title: A currency that expires every winter
title_es: Una moneda que caduca cada invierno
dek: Money that loses a little each month and turns into firewood on the shortest day.
category: ideas
number: 8
date: 2026-10-19
needs_summary: a town willing to run it for one year
needs:
  - A council willing to run it for one season
  - A local bank to hold the backing
---

## First section

Text…
```

| Field | Required | What it does |
| --- | --- | --- |
| `title` | yes | Title on the article, the contents strip and the landing panel. |
| `title_es` | no | Spanish title. Falls back to `title`. |
| `dek` / `dek_es` | no | One or two sentences under the title on the article page. |
| `summary` / `summary_es` | no | Shorter line for the contents strip. Falls back to `dek`. |
| `category` | yes | `ideas`, `architecture`, `ideology`, `essays` or `influences`. Picks the sign and the landing key. |
| `number` | yes | Issue number, shown as `08`. |
| `date` | yes | `YYYY-MM-DD`. Sets the order (newest first). |
| `reading_time` | no | Minutes. Computed from the text (200 words a minute) if left out. |
| `needs_summary` / `needs_summary_es` | no | The "Needs" stamp on the contents strip and article header. |
| `needs` / `needs_es` | no | List under "Maybe you do." at the end of the article. |
| `needs_label` / `needs_label_es` | no | Text beside that list's stamp. Default: "what it takes". |
| `lead` | no | `true` puts this entry in the cut-out instead of the newest one. |
| `sample` | no | `true` marks placeholder content; the pages show the "sample entries" note. |
| `draft` | no | `true` leaves the file out of the site completely. |

Article bodies are written in English; in Spanish the page says so and translates the title, dek
and chrome. Category names, the landing statement and other fixed copy are in
`src/_data/categories.json` and `src/_data/site.json`.

### Markdown conventions

Ordinary markdown works: paragraphs, lists, links, `inline code`, tables and blockquotes. Plain
HTML is allowed too, for example a table that needs a caption. On top of that:

| Write | You get |
| --- | --- |
| `## Heading` | A section heading, numbered in the margin automatically. `###` is a subheading. |
| `::: note 1` … `:::` | Margin note 1: left of the text on wide screens, a box in the flow on phones. Put it just before the paragraph it belongs to. |
| `[^1]` | The small boxed reference to note 1 inside the text. |
| `::: pull` … `:::` | Pull quote: the inked cut-out. |
| `::: figure Fig. 1` … `:::` | A figure. An optional first line `![alt text](image.png)`, then the caption. The image is dithered to 1-bit on the page; with no image, the page draws a labelled placeholder. |
| ```` ```ledger rule ```` | A code block. The text after the backticks becomes its label. |
| `> -- Name, Source` | In a blockquote, a paragraph starting with `-- ` is the attribution. |

Put images in `src/articles/images/` and link them as `/articles/images/name.png`. They are copied
as they are, and the page dithers them when it loads. Use images from this site, not from other
domains: the browser won't let the page read pixels from another site, so those stay undithered.

## Publishing

Merging to `main` publishes the site. `.github/workflows/pages.yml` runs `npm ci` and
`npm run build`, then deploys `_site/` to GitHub Pages. It can also be started by hand from the
Actions tab. One-time setup: in the repository, go to Settings → Pages → Source and choose
**GitHub Actions**.

Links are written as root paths (`/articles/`) in the templates. The build adds the `/revolution/`
prefix. To build for another prefix, set `PATH_PREFIX`, for example `PATH_PREFIX=/ npm run build`.
